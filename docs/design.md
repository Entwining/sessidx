# Design

## Ownership and storage

One Rust package discovers four read-only session roots, two of them Codex's active and archived directories, and streams complete JSONL records through harness adapters. SQLite uses bundled FTS5, WAL with a 10,000-page autocheckpoint for the writer, foreign keys, an 8 MiB connection page cache, and an OS-released advisory writer lock. Persistent setup and schema writes happen only while holding that lock. An initialization race returns writer-busy coverage rather than bypassing the lock.

`files` owns locations, event details, sessions, and shapes. `locations` retains exact file/line/byte offset/length pointers, SHA-256 range digests, ordinals, native identity, timestamps, and model/session references. Locations and event details store hashed event/call identities and raw-range digests as 32-byte BLOBs. Repeated metadata, including session IDs and source labels, is interned as integer references in `strings`. `event_details` exists only for logical events; context locations derive their constant role, kind, and missing outcome fields. These locations remain necessary for filtered raw reads, `show path:line`, and native deduplication. The `events` view exposes the original textual columns and lowercase hexadecimal hashes to queries. The string lookup cache is local to each file transaction, so a rollback cannot leave cached references to uncommitted rows. Tool results retain pointers, outcomes, denial metadata, and a redacted text prefix of at most 2 KiB with a truncation flag. Unknown records retain a context pointer (location and range digest), their structural type/subtype/key signature, and coverage counts, never their body.

FTS indexes a Han-spaced copy of redacted message/input text and tool output prefixes in a contentless-delete table. The stored body exists only in events; search snippets read that body. The bundled SQLite supports DELETE on this contentless-delete table (added in 3.43.0), keeping the token positions phrase queries need. A delete does not lower the row count or total token length that BM25 ranking uses, so after files are replaced or deleted, ranking drifts slightly from a fresh build until `index --full`. Phrase queries preserve contiguous character order; Latin words retain `unicode61` semantics. Full tool outputs and deferred compaction/branch reconstruction remain outside FTS. Prefix extraction clips before redaction and again afterward if redaction expands the text; both cuts respect UTF-8 boundaries. Outcome classification still receives the complete result, independently of the stored prefix. Content-bearing Claude diagnostic attachments use the tool role and `tool_output` kind without inventing native tool results.

## Incremental indexing and recovery

An unchanged file needs matching device/inode, length, and nanosecond mtime/ctime, and a previous pass that did not run out of budget. A growing file resumes when device/inode and its stored prefix hash agree. Prefix length is stored, including files shorter than 4 KiB. Otherwise owned rows are replaced in one transaction. Carry state preserves session/model attribution across append refreshes. This follows the chosen append contract: a writer that changes old bytes beyond the prefix while also appending is not detected by the prefix test; range display still rejects changed bytes.

Codex can replace a rollout idle for seven days with a byte-identical `.jsonl.zst` sibling (its `local_thread_store_compression` feature or the `rollout/compress` request) and restores the plain file, then appends, when the thread resumes; archiving renames either form. A session file is identified by its plain `.jsonl` path: discovery maps `.jsonl.zst` to that path with one entry per pair, and opening tries the plain file, the compressed one, then the plain file again: Codex publishes a new form before removing the old, so the retry resolves a change of form between two attempts. Offsets, lengths and range digests address decoded bytes, so records keep their `path:line` across the change. A change of form is a new inode and reindexes the file. Codex's temporary files end in `.tmp` and are not sessions. A compressed source is decoded from its first frame across any number of frames; content zstd cannot decode is one parse error (`invalid_zstd`) after the records decoded before it, and is not decoded again until the file changes. A file deleted or archived between discovery and opening loses its rows, like one missing from discovery.

Claude/Pi content blocks already ignored by the adapters (thinking, images, and fallback) are validated as borrowed RawValue spans and reduced to their type before materialization. Multi-megabyte Pi thinkingSignature strings remain solely in the raw source; message identity/counts and byte digests are unchanged. Normal text, arbitrary tool inputs, and unknown block types still materialize normally. Only complete newline-terminated records advance the cursor. `index_status` distinguishes ready, deferred_tail, and budget_exhausted. A stable partial tail is not reread on every query, does not mean indexing failed, and resumes when the file changes. Records above 16 MiB are streamed past and counted as parse errors. Explicit indexing is unbounded; refresh on search/show/count/doctor receives two seconds, including discovery, and returns committed complete records with staleness and a continuation file. Filesystem operations and an individual SQLite operation are not interruptible by this deadline, so two seconds is a refresh budget rather than a strict end-to-end latency guarantee.

The writer lock covers initialization, full reset, discovery reconciliation, and per-file transactions. A missing root that holds indexed files keeps its rows and prevents complete-coverage claims; one that never held any, such as a harness the user does not run or a Codex archive directory not yet created, does not affect coverage. A full rebuild refuses while such a root is missing, because its reset would drop the rows that keep later refreshes stale; recovery restores the root or rebuilds with `--root` for the roots that remain. Deleted files within present supplied roots lose their owned rows. Full rebuild drops derived child tables before source tables and recreates the schema transactionally, then vacuums the empty database to release old pages; FK event indexes also keep individual file replacement from scanning every command/denial row.

Schema version 4 added cache identity, replacement/rebuild invalidations and monotonic location IDs for pagination snapshots; version 5 defines `canonical_events` by probing for an earlier copy instead of ranking every copy. A normal open, including read-only SQL, rejects older schema versions with one recovery instruction: `run sessidx index --full`. Explicit full indexing opens the old database, acquires the writer lock, and rebuilds derived tables; contention leaves the old schema intact. The sources are never migrated or modified. Unknown schema versions are rejected rather than treated as an index owned by this binary.

Display and scanning validate device/inode and the stored SHA-256 of the exact range; a range past the end of its source is unavailable. A plain source is read only at the range. A compressed one is decoded forward from its first frame, once per file for ranges in increasing order. A replaced, truncated, or rewritten range contributes unavailable coverage. Shared session filters first resolve strings/file paths through their unique indexes, then select location IDs through session/file indexes. A grep progress handler covers SQLite preparation and stepping from the start of its scan budget; an interrupted first step yields incomplete coverage and an unchanged continuation. Raw filesystem reads remain non-interruptible. Raw regex matching precedes display redaction; grep/show pagination retains an event cursor and incomplete coverage in the final JSON record.

Cursors bind the query and filters to a cache identity, event high-water mark, invalidation revision and continuation. Appends cannot enter later pages; replacement/deletion invalidates a cursor only if removed events are at or below its mark, and a full rebuild invalidates all cursors. Search carries the initial session order because live FTS corpus statistics can rescore existing matches after appends. The order covers only the first 100 sessions, each anchored by its lowest matching event ID, which cannot change below the high-water mark, so the cursor stays small however many sessions match. Hits within a selected session use current FTS scores over the bounded event set. Cursor checks and the query share a SQLite read transaction.

SQL performs no refresh, holds a nonblocking shared lock when the writer is idle, and marks reads stale/incomplete when the writer lock is held. Duplicate output names after redaction require unique aliases. It runs one readonly SELECT/WITH with a two-second progress handler and 10,000-row result bound; exceeding either fails the operation.

## Privacy and limits

Body text, tool inputs, and argv pass recall-leaning redaction before storage. Patterns cover private-key PEM blocks, Bearer/Basic authorization, known token prefixes, credential assignments/headers including key:, and quoted multiword values. JSON objects are decoded first, and credential-like keys suppress their complete values. Text assignments and JSON fields share one credential-name detector; its names are listed in the `docs/formats.md` rows `credential_name` and `credential_name_suffix`. Pure hex, 0x-prefixed hex, UUID, RFC 3339 timestamps, multi-component absolute paths, and email shapes survive entropy alone. For absolute paths and identifier-shaped relative paths, up to two nonempty ASCII-digit suffixes (:line or :line:column) are removed before entropy exemptions only when the remainder contains `/` or `.`; remaining high-entropy runs still use their original bytes for entropy. URLs keep their scheme and host; each path segment and query value is checked separately by the hex, UUID, identifier-shape and entropy rules. A leading slash without multiple path components is not a path; such a run is exempt only when it is identifier-shaped, and otherwise the entropy threshold decides. Identifier-shaped runs also survive entropy alone: after removing trailing sentence punctuation and an optional one- or two-hyphen flag prefix and a leading `/`, splitting on / and then on ., ::, - and @ must leave nonempty pieces of ASCII letters or underscores followed only by optional trailing digits, or all-digit pieces when another piece contains an ASCII letter. `.`, `..` and `@` segments, leading dots and one leading `@` per segment are path structure. Internal empty pieces remain invalid. Credential fields, assignments and known prefixes are redacted before this exemption. Remaining symbol-bearing/base62/base64-like runs of at least 16 characters with Shannon entropy at least 3.5 bits/character are suppressed. A smaller length or entropy cutoff redacts more aggressively. Han prose is outside the run detector.

Session IDs, models, tool/program names, and structural discriminators receive recognizable-pattern redaction without body entropy suppression. Source file paths and refresh continuation locations retain their exact spelling so callers can open them. These fields are operational metadata, not a place for credentials. Range display redacts decoded JSON keys and values again; SQL and diagnostics redact their textual output. No stored representation or diagnostic contains a raw output copy.

This is heuristic redaction, not a guarantee that all secrets can be recognized. An unmarked secret with a pure hexadecimal, UUID, path or identifier shape can survive; credential context or a known prefix is required for those values. This accepts unmarked random values made entirely of letters: for uniformly sampled alphanumerics, that subset is about 6% at length 16 and 0.36% at length 32, before accounting for additional identifier-shaped values with trailing digits or all-digit pieces, such as a letter run followed by `-` and a digit group. Redaction analyzes JSON values independently and does not reconstruct a secret split across fields; fragments that individually evade the patterns or entropy cutoff can remain recoverable together. Bare base64 below 16 characters is outside the run detector, and values of 16–23 characters still depend on the entropy cutoff; being shorter than 24 is not itself enough to determine redaction. Short/low-entropy secrets, non-ASCII credentials, and secrets disguised as operational metadata can also survive. Structured value recognition can over-redact ordinary keys containing `token` or `secret`. Synthetic shaped and unmarked non-hex high-entropy canaries cover user messages, tool inputs, outputs, the live database/WAL/SHM, every CLI command, stdout, and stderr. Context-labeled hex has separate controls. Those checks establish the tested partitions only. Any newly observed leaking canary is a failed gate, not proof that the heuristic is safe elsewhere.

## Counting and attribution

`events` preserves observed records. `canonical_events` chooses one event per harness/native ID/kind; absent IDs remain unique rows. Claude assistant fragments use message ID before transcript UUID. Native IDs deduplicate inherited copies without comparing text, so independent identical messages and retries remain separate. The earliest first-record timestamp chooses copy ownership, with path/line/ordinal as deterministic ties. Each event is compared only with its own copies, so a query narrowed to a session or time range reads only those events and their copies. Missing or tied start timestamps cannot establish the true origin. Recorded parent IDs are retained, but no ancestry is invented and no Pi branch/context-edit reconstruction is performed.

Models come from Claude message metadata with carry-forward excluding `<synthetic>` as a switch, Codex turn_context, and Pi explicit message model/model_change. A synthetic assistant still retains its explicit synthetic model. A speaker role is separate from session kind and both preserve their field source. Only explicit Claude sidechain/Codex subagent evidence produces delegated kind; otherwise kind is unknown. User-role messages can include injected instructions, so they are not necessarily human messages. Codex instruction hashes identify recorded base text, with injected AGENTS.md text as fallback; they do not prove instruction loading or adherence. Claude/Pi instruction inference is deferred.

The three CLI metrics use different units:

| Metric | Numerator | Denominator | Unclassified |
| --- | --- | --- | --- |
| commands | Parsed static sites, optionally selected by program | All parsed static sites in the filter | Unparsed shell calls or sites with unresolved program |
| failures | Selected native calls with failed call-level result | Selected native calls, including missing results | Missing outcome or unresolved program selection |
| denials | Selected native result events with qualified denial metadata | Selected native result events | Unknown denial reason or unresolved program selection |

`count` applies the `canonical_events` and `call_outcomes` rules to the base tables, limited to tool calls and results before ranking copies, so it does not join every event's strings first; `count_view_parity` in `docs/formats.md` keeps its rows equal to the same counts over the views.

A denial event with multiple envelopes counts once in `count`; `denials` preserves individual recognized source/reason rows for SQL. Claude/Pi booleans provide flag evidence. Codex decoded shell transports (including custom-labeled transport objects), MCP transport isError, leading script/process prefixes, and Promise rejections provide text evidence. A transport Boolean is distinct from a native Codex error flag; failed items win over later successful items. Complete rejection fields after a parsed value in a truncated block remain qualifying evidence. Generic inner error wording is not a failure, exit zero does not classify every inner command, and transport stdout is not recursively treated as another result. Results with no qualifying evidence remain unknown. Failed evidence wins when multiple result records join the same harness/session/call identity; no per-command exit status is inferred. Codex hook markers must be the first nonempty payload line after a leading Script error header; later file-dump quotations do not qualify. Claude permission-refusal text without a native mechanism is labeled native_denial, not classifier. Textual leading reason sentences map to stable reason IDs and may recognize historical wording that does not equal the complete current guard constant.

Some counts need data v1 does not persist: per-batch-item results, full output-block classification, branch diagnostics, and inner stderr failure heuristics. They cannot be reproduced through SQL from output prefixes and pointers; answering them means reading raw ranges with `grep` or `show`, not extending the schema to copy outputs or reporting zeros.

## Shell command sites

Brush walks simple commands, pipelines, conditions, loops, functions, command/process substitutions, and expandable heredocs. This measures syntax sites, including untaken branches and function bodies. It does not resolve aliases, `env`/`command` wrappers, quoted shell `-c` bodies, dynamic programs, parameter/arithmetic expansions, or extended-test substitutions.

Codex exec wrappers use a regex locator for literal cmd fields (`cmd`, `"cmd"` or `'cmd'`) in direct tools.exec_command object calls, regardless of field position. Quoted data, comments and regex literals following expression-start punctuation are skipped. Metadata scanning skips a single level of nested objects and flat arrays. A literal must end the field; concatenations, variables, duplicate cmd fields and interpolated templates remain opaque. A spread or computed property after cmd can override it and also makes the call opaque; those members only before cmd leave the literal extractable. Strings, comments and regular expressions inside metadata are skipped when checking that order. The decoder follows the [ECMAScript string and template value rules](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-literals-string-literals) for quotes, identity/control escapes, hexadecimal and four-digit Unicode escapes, line continuations and CRLF template normalization. Braced Unicode, surrogate escapes and invalid numeric/hex escapes are unsupported and remain unparsed. Shell-tool references with any receiver or none contribute one opaque site if no literal yields a parsed site; mixed unsupported references also retain one opaque site. Regex extraction does not validate the entire JavaScript source and can recover a literal call despite malformed syntax elsewhere. It never evaluates JavaScript or resolves names/aliases.

Parser refusals, sources above 256 KiB and Brush traversal beyond depth 64 remain unparsed. These limits and the unclassified count must accompany program-frequency claims; static sites never establish executions.

## Dependencies

All direct versions and Cargo.lock are pinned. Brush, bundled rusqlite, and serde_json are the core dependencies. Each other crate replaces code that would otherwise be hand-written: serde derives persisted state/output; anyhow removes error-conversion boilerplate; regex supplies scan/redaction matching; chrono supplies timestamps/weeks; sha2 supplies fingerprints and hex their lowercase encoding; walkdir replaces recursion; clap supplies CLI validation; zstd decodes Codex's compressed rollouts. zstd-sys has always compiled the zstd C library, which is BSD-3-Clause or GPLv2, and releases of the three zstd crates since zstd 0.14 declare BSD-3-Clause themselves, so `deny.toml` allows that license for those crates only. Standard-library File locks are nonblocking and released on close. Test-only tempfile owns isolated fixture/database cleanup. rusqlite hooks provide the SQL deadline, its fallible_uint feature keeps `u64` and `usize` columns, which fail rather than wrap above `i64::MAX`, and its existing statement cache avoids preparing per-record INSERTs again. The serde_json raw_value feature avoids owned decoding of opaque blocks. `about.toml` and `about.hbs` describe the license notices of the crates compiled into the binary: the Homebrew formula renders them into `LICENSE-THIRD-PARTY.md`, which Homebrew installs with each bottle, and CI renders them so a license they cannot place fails before a release rather than during one.
