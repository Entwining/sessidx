Run `sessidx index --full` after upgrading. The schema version is now 5, and until the rebuild every command stops with `database schema changed; run sessidx index --full`. The rebuild also applies this release's redaction changes to text indexed earlier.

Codex sessions that 0.0.1 missed are now indexed: threads Codex has archived under `~/.codex/archived_sessions`, and rollouts Codex has compressed to `.jsonl.zst`, which keep their plain `.jsonl` path in results and are read by `show` and `grep` like plain files.

Redaction keeps more lookup keys searchable: relative and dotfile paths, scoped packages and `@/` import aliases, versioned file names, dated model IDs, and RFC 3339 timestamps, which had masked about a third of the `ts` values `sql` returned.

Counting and lookup are faster. `count failures` takes about 3 s instead of 6 to 12 s on the maintainer's logs, and `count denials --program rg` about 6 s instead of not finishing within 15 minutes. `grep` and `show` do less work per row. `canonical_events` and `call_outcomes` narrowed to one session answer within milliseconds instead of exceeding `sql`'s two seconds, and a query that does hit the deadline now says how to narrow it. A full index is 7 to 13% faster.

Other changes callers may notice: `missing_roots` lists each absent root as the `HARNESS=PATH` that `--root` accepts; an invalid flag value fails before the index refreshes, with one `end` record naming the flag; `--by` with an empty value is an error; and a continuation cursor issued by 0.0.1 for a date-only `--since` or `--until` must be restarted.

The bundled skill changed as well, including how to count sessions in `sql`, where search pagination stops, and what a refresh `continuation` asks of the agent. Run `gh skill update sessidx` to pick it up. The skill can now also be installed as a Claude Code plugin or with `npx skills` for Claude Code, Codex, Pi, and other agents; the README lists the commands.
