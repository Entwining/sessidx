Run `sessidx index --full` after upgrading. The schema version is now 15, so queries fail with that recovery instruction until the index is rebuilt, which takes several minutes for a full history. The rebuild also covers the new parser version, 6.

Update the skill too. Claude Code does not update plugins from third-party marketplaces by default, so run `claude plugin update sessidx@entwining`, or enable auto-update for the `entwining` marketplace under `/plugin` as the README describes. Codex updates the plugin when it starts, and Pi updates with `pi update git:github.com/Entwining/sessidx`. Plugin installs already carried the skill text for most of the changes below, so until this release an agent could ask an installed binary for fields and functions it did not have.

A `search`, `grep`, or `show` page now starts with a `begin` record that repeats the page's `complete`, `stale`, and `returned` from `end`, with `more` true when `end.next` is set, so output cut to its first lines with `head` or `cut` still shows whether it is the whole result. `end` is unchanged and still the only record with the cursor. A filter that reads records by position or counts lines sees one more record; one that passes non-data records through, as the skill's examples do, is unaffected. Errors still print only `end`.

A `grep` hit now carries `text`, its redacted record's JSON text, instead of `record`: whole up to 512 bytes, and otherwise the 512 bytes around the first match, with a `cut` entry for `/text`. Before, a record larger than a page was shown as `part` from its first byte, which often left the match off the page. A filter that read `.record` from a grep hit should read `.text`, which parses as JSON only when the hit has no `cut`; `sessidx show REF --around 0` still reads the whole record. A hit whose match redaction removed from the text carries `"match_located":false`.

`sql` has a `fts_query(terms)` function that returns the full-text expression `search` matches, so `id IN (SELECT rowid FROM fts WHERE fts MATCH fts_query('permission denied'))` selects events by words across the whole history where a `text LIKE` scan ran out of the two-second limit. It matches whole words and phrases in the indexed text, not substrings.

`search` and `fts_query` now refuse a bare uppercase `OR`, `AND`, or `NOT` with an error saying that terms are joined with AND. Before, `sessidx search 'foo OR bar'` also searched for the word "or" and returned an empty result marked complete. Quote the word to search for it.

A Claude Code tool result without an `is_error` flag now counts as a success, as Claude Code itself treats it, and `call_outcomes.ok_source` names this evidence `default`. About two in five Claude Code tool calls had an unknown outcome before, so `count failures` now reports far fewer `outcome_unknown` calls for Claude Code.

A prompt typed while Claude Code is busy is now indexed as a user message. Claude Code records it as a queued attachment and often never repeats it as a user record, so `search` could not find it.

The `events` views carry `call_event_id`, the `id` of the call a tool result answers, so `sql` joins a result to its call by primary key. A join on `call_id` read every event and could pass the two-second limit. `sessions.instruction_hash`, which nothing read, is removed.

A refresh that cannot take the writer lock now reports the index's parse errors and missing roots in `end.refresh`; before, they read 0 and empty.

Timestamps are now parsed with jiff instead of chrono, which is unmaintained. Every RFC 3339 form the agents write reads as before; a second of 60 is stored as 59, more than nine fractional digits or a U+2212 minus sign is refused, and ISO 8601 spellings such as `20261001T00Z` are now read. The bundled SQLite is now 3.54.1, which fixes RUSTSEC-2026-0459.
