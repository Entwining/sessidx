Run `sessidx index --full` after upgrading. The schema version is now 7, and until the rebuild every command stops with `database schema changed; run sessidx index --full`.

Update the skill too, because the old one tells agents to use options this release rejects. Claude Code does not update plugins from third-party marketplaces by default, so run `claude plugin update sessidx@entwining`. Codex updates the plugin when it starts, and Pi updates with `pi update git:github.com/Entwining/sessidx`. If you installed the skill with `gh skill` or `npx skills`, either keep updating that copy with `gh skill update sessidx` or `npx skills update -g`, or switch to the plugin or package command the README now gives for each agent. To switch, first remove the old copy, with `npx skills remove --global sessidx` or by deleting the directory `gh skill list` shows for it: an agent finds both copies, and Pi keeps whichever it loads first.

The dimension that tells Claude Code, Codex, and Pi apart is now `agent`: `--harness` is `--agent`, `--root` and `missing_roots` use `AGENT=PATH`, `--by` groups by `agent`, and output records and SQL columns say `agent`. The values `claude`, `codex`, and `pi` are unchanged. The session-kind filter and grouping are `--session-kind` and `session_kind`, with the values `main`, `subagent`, and `unknown` in place of `delegated` and `unknown`.

Count rows name what they count instead of `unit`, `numerator`, `denominator`, and `unclassified`, and the counts of a metric add up: `count failures` reports `calls` as `failed` + `succeeded` + `outcome_unknown`; `count commands` reports `sites`, of which `sites_without_program`, and `unparsed_calls` outside them; `count denials` reports `results`, of which `denied`, of which `denied_reason_unknown`. Every row carries its `metric`, and with `--program` its `program` and `matching_sites`, `calls_with_unresolved_program`, or `results_with_unresolved_program`. `doctor` names each count after the rows it counts, and `tool_events_without_model` replaces `unknown_models`, which counted context and user messages too.

Each transcript file is now one session, whose ID, parent, kind, and starting directory come from its own header, file name, or records rather than from history copied into it. A Codex subagent thread no longer takes its parent's thread ID and directory, and a Codex thread resumed from its own history no longer names itself as its parent. A Claude subagent transcript is its own session keyed by its `agentId`, with the session that spawned it in `parent_id`, instead of being reported under the parent's session ID, and history copied at the start of a resumed Claude session belongs to the resuming session. `show` and `--session` also accept a transcript path, and an ID that names more than one transcript, such as a Claude subagent ID repeated under another parent, is refused with the transcripts' paths. Claude workflow journals are no longer indexed.

Lookup records changed shape. `search` session records carry the session's kind, parent, starting directory, and `started_at`, its first timestamp, and no longer carry `ts`, the latest matching hit time; hits carry `text` and `truncated` instead of `snippet`. `grep` and `show` return the parsed, redacted source line in `record` instead of a JSON string; for a range whose source changed, `show` returns `unavailable` with the reason, and `grep` skips it and counts it in `end.unavailable_ranges`. `sql` relations changed with the schema, and `canonical_events.copy_rank` (always 1) and `commands.outcome_scope` (always `call`) are gone; list a relation's columns with `sessidx sql "SELECT name FROM pragma_table_info('events')"`. `events` reads text only when a query names it, so whole-history aggregates over event metadata are faster. Claude's message `kind_source` now reads `root.type,message.content` instead of coming back redacted, and `model_source` is `none` exactly when `model` is null.
