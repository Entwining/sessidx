Codex updates the plugin when it starts, and Pi updates with `pi update git:github.com/Entwining/sessidx`. The skill now tells agents to answer token and compaction questions with `count usage` and `count compactions`, and how to read their columns.

sessidx now indexes the token usage each model request records (#58). `count usage` reports `requests`, each counted once under its own model, and `passes`, each under the model that ran it, so an advisor's model can show passes and tokens with no requests. Token sums add up over passes. `input` excludes cached and cache-written tokens for every agent, so the prompt is `input` + `cache_read` + `cache_write`, and `reasoning` is part of `output`. A field a record omits is not counted as zero, and each optional sum has a `*_recorded` count beside it. `count compactions` reports `compactions` = `auto` + `manual` + `trigger_unknown` with the context sizes before and after. Both group by `agent,model,week` by default and refuse `--by role`, `--role`, and `--program`. `sql` gains the views `requests`, `request_passes`, and `compactions`; on Pi, `compactions` also carries the usage of the calls that wrote the summary, which `count usage` does not include.

A Claude message written as several records, or copied by a resumed transcript, counts as one request, taking its finished record's usage. A Codex `token_count` counts as a request only before the rollout writes its first `token_usage_record`, and only when its running total moved. Forks made by Codex builds that wrote no `token_usage_record` copy their parent's running totals, and those totals count again in the fork; on the maintainer's logs that is 26,882 records in 345 rollouts. Route evidence and request errors are not indexed.

A bare `sessidx` now prints its help text instead of a JSON error, and still exits 2.
