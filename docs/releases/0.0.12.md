Run `sessidx index` after upgrading. The schema version is unchanged, but the parser version is now 5, so every transcript an earlier release indexed is read again. No indexed row changes: the parser sources were split into smaller functions without changing what they read. Until the reindex finishes, each query except `sql` spends what its two-second budget leaves after new records on it, most recently changed transcripts first, answers the rest from their earlier rows, and reports `stale` with a `continuation`. `sessidx index` reindexes a full history in several minutes and then compacts the database, which needs free disk space up to twice its size while it runs.

Update the skill too. Claude Code does not update plugins from third-party marketplaces by default, so run `claude plugin update sessidx@entwining`, or enable auto-update for the `entwining` marketplace under `/plugin` as the README describes. Codex updates the plugin when it starts, and Pi updates with `pi update git:github.com/Entwining/sessidx`. The skill now says that `sql` answers only from what earlier commands indexed, that a `max_ts` there does not show that a session ended, that an answer depending on the current logs needs `sessidx index` first, and that a cursor's pages, even a complete last one, miss records written after its first page.

`sql` now reports `stale: null` in its `end` record and in `end.refresh`, because it does not refresh and nothing compares its rows with the logs (#83). It used to report its writer lock probe as `stale`, so with no writer holding the lock, an answer that missed records appended since the last refresh ended with `stale: false`, the same as one given right after a refresh. A writer that holds the lock when `sql` starts is now reported only in `end.refresh.writer_busy`, and the result stays `complete: true`, because it holds every row the query selected from committed data; before, it reported `stale: true` and `complete: false`. That writer may be partway through indexing, such as during `index --full`, so the committed rows can be a partial index. Exit codes are unchanged. A caller that waited for `sql` to report `stale: false` should instead run `sessidx index` and check that its `end.stale` is `false`.
