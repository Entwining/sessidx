Run `sessidx index --full` after upgrading. The schema version is now 11, and until the rebuild every command stops with `database schema changed; run sessidx index --full`. The rebuild ends by compacting the database, which needs free disk space up to twice its size while it runs. Cursors from earlier releases are refused; restart the query without `--cursor`.

Update the skill too. Claude Code does not update plugins from third-party marketplaces by default, so run `claude plugin update sessidx@entwining`, or enable auto-update for the `entwining` marketplace under `/plugin` as the README describes. Codex updates the plugin when it starts, and Pi updates with `pi update git:github.com/Entwining/sessidx`. The skill now tells agents to run `sessidx index` when the views changed, when a refresh reports a `continuation` after an upgrade, or when a search error asks for compaction, with a timeout of at least ten minutes or in the background.

Later upgrades need `index --full` only when the index's tables change. Each transcript records the parser version that indexed it, and refreshes reindex the transcripts an earlier parser indexed, most recently changed first and within their two-second budget, reporting `stale` with a `continuation` until they finish or `sessidx index` runs. Any refresh recreates views an earlier release defined differently, and `sessidx index` builds changed indexes.

Counts, `doctor`, `canonical_events`, and `call_outcomes` now read facts the indexer stores and per-day rollups instead of deriving them from every event on each query. On the maintainer's logs, a warm whole-history `count failures` fell from about 1.6 s to 0.2 s, and a cold `count denials --program rg` from about 2.3 s to 0.3 s. A tool result now takes its program from any copy of its call in its session, so results that a Codex or Pi fork recorded for a copied call count under their program again; 633 such results on the maintainer's logs had lost it. `events` gains `canonical`, and `sessions` gains `min_ts` and `max_ts`.

`grep` now reads the selected sessions' transcripts one at a time instead of scanning every event, so its work follows the sessions its filters select: on the maintainer's logs, `grep --agent codex` used to spend its two seconds without examining a range, and now returns 20 hits in 1.7 s. Its cursor resumes after the last range it examined. `grep` and `search` cursors are refused only when a transcript they have yet to read changes, so they survive Claude Code deleting transcripts older than 30 days.

`search` now stops after two seconds instead of running without bound, with an error that says to run `sessidx index` when compaction is due and otherwise to search again and then add distinctive terms. A later page passes over a frozen session that stopped matching instead of returning an empty page or a session twice. `search` and `grep` start their two seconds after the refresh's, so either can take about four seconds before it answers.

On the maintainer's logs, a cold `search error` that first refreshed five grown transcripts took about 5 s with 0.0.7 and about 1.3 s with this release. With no pending changes, a cold `search error` on an index this release wrote without compacting took 2.4 s or more, past the new search deadline, and about 0.9 s once compacted, as on a clean build, so the query and storage changes alone do not account for the gap; 0.0.7 was not measured without pending changes. 0.0.7 never compacted after indexing: `index --full` vacuumed the emptied database before rebuilding it. These figures come from different snapshots and conditions, so compare them as magnitudes.

`sessidx index` now compacts the database when more than half of its records were written since it was last compacted, as after a first index, a rebuild, or a parser change. A refresh before a query never compacts, so an index kept current only by queries comes due once its history doubles; a failed compaction leaves the index answering queries.

Refreshes delete the rows of vanished transcripts after indexing new records and within their budget, instead of before the query without one. `sql` no longer holds the writer lock while it reads, so refreshes during a long query no longer report a busy writer.
