# sessidx

sessidx indexes local Claude Code, Codex, and Pi session logs into SQLite for two uses: lookup (find the session where something happened, the context behind a commit, a past failure) by people and by agents, and retrospective counting by agent, model, role, and week with honest denominators. It replaces grepping gigabytes of logs per question and rewriting throwaway parsers per retrospective, which produced contradictory counts. Agents reach it through the [`sessidx` skill](skills/sessidx/SKILL.md), which requires `sessidx` on `PATH`.

Change the owner, not a copy. A rule without a `docs/formats.md` row and a fixture whose test fails when the rule is removed is not finished. Agents that use sessidx learn it from the skill alone, so a change to the CLI contract also changes the skill in the same commit. Put a rule in the strongest mechanism that can hold it: a type, then a lint in `clippy.toml` or `Cargo.toml` `[lints]`, then a test or CI check, and prose only for what none of them can enforce. `clippy.toml` already enforces the no-environment-variable decision below, and every lint suppression needs a reason.

## Decisions to keep

Each of these was argued and measured; reopen one only with new evidence, not on general reputation.

- **Rust.** Go was proposed for its shell parser's maturity. On the maintainer's real commands `brush-parser` matched it. Brush stays pinned exactly.
- **Raw logs are the source of truth and are never written.** The index is derived and can always be rebuilt with `index --full`.
- **Redacted text is stored.** The alternative, storing no text, was rejected by the user. Redaction leans toward recall, but identifiers are lookup keys and must stay searchable: paths and `path:line` locators, session and thread IDs, hexadecimal runs, UUIDs, timestamps, and code identifiers such as `tools.exec_command`. A secret in one of those shapes is caught only by credential context. A change to the run pattern or its exemptions can silently redact hundreds of thousands of identifiers, so count redactions on a real-text sample before and after, by shape, without printing values. A value parsed out of log text into its own column, such as a reason marker's producer and reason, is stored only when redaction leaves it unchanged, so no column holds what the stored text lost.
- **Tool outputs are pointers plus their first 2 KiB in full-text search.** On held-out "find the session where this error happened" cases, `search` found all 42 with the prefix and none without it; the only fallback, `grep` narrowed to an agent and month, found 14 and completed 3 within its deadline. The prefix costs about a quarter of the database and some ranking noise when output text outranks a message. Full outputs would multiply size and secret exposure; the rest is reached by `grep` or `show`.
- **Chinese text is matched as phrases over a character-spaced copy** in FTS5 `unicode61`. Trigram tokenization was rejected because queries under three characters fall back to a full scan.
- **Codex code-mode commands are taken only from `cmd` string literals** in the wrapper source; nothing evaluates JavaScript (user decision). Anything else in a wrapper that references a shell tool stays one unparsed site, so it is counted in `unparsed_calls` instead of disappearing from `count commands`.
- **Refresh happens on query within a two-second budget.** There is no daemon or LaunchAgent. Never raise the budget to hide a slow path, and never let a query wait without bound on the writer lock: a wedged refresh that holds the lock blocks every later query. Deleting the rows of vanished transcripts counts against the budget too, after new records.
- **Counts name what they count and partition their population**, as `calls` = `failed` + `succeeded` + `outcome_unknown`, and name what lies outside it apart. A generic numerator, denominator, and unclassified once mixed parts inside the denominator with parts outside it, in different units per metric. Shell command sites are static syntax and never prove execution. Inherited history is deduplicated only by native IDs, never by identical text.
- **Guards declare their denial reasons; sessidx does not learn their wording.** A reason comes from the agent's own structured fields or from a producer-neutral reason marker read the same way for every producer (#56). The table of the maintainer's past guard sentences is frozen: a sentence or a producer-specific case added for a new guard, agent-guard included, ties sessidx releases to that guard's wording and still leaves every other guard `unknown`. Structured hook fields cannot carry the reason, because Claude Code drops unknown fields, Codex fails the hook on one and runs the command, and Pi passes only a block flag and reason.
- **A transcript file is one session, identified by its own header or name.** Copied history carries other sessions' IDs: taking the last one misattributed 201 Codex subagent threads to their parents, and taking a Claude main transcript's first record can name the session it resumed. A separate transcripts table was considered and dropped because transcripts and sessions are one to one apart from a few shared IDs, which selectors refuse with their paths.
- **Facts that depend on other rows, and the sums counts report, are stored by the writer**, not derived per query: whether an event is the first copy of its native event, a tool call's outcome, and `daily_counts`, the per-transcript, per-day sums behind `count` and `doctor`. Derived per query the first two were nine tenths of a whole-history scan, 1.5 s warm over `call_outcomes`; stored, 0.2 s. Summed per day, a whole-history count reads 68,717 rows instead of 2.2 million events. The writer keeps them equal to their definitions after every commit (`derived_facts` and `daily_counts` in `docs/formats.md`) and reads only the keys a transaction touched (`derived_work`), and a change to a definition changes its maintenance in `src/store.rs` and that test's reference query together.
- **Event bodies stay out of the event row** and the `events` view reads them only through subqueries. Joined in, they made every whole-history aggregate read about half the database. Storing role, kind, model, and labels inline instead of interned costs about 6% of the database and removes the `strings` table agents joined by hand.
- **The Claude Code, Codex, or Pi dimension is `agent`.** Schema 6 renamed it from `harness`, a coined term the user rejected; agentsview, cass, and ccusage call it `agent`, and the vendors describe these products as coding agents.
- **No production switches.** No config file, environment variables, or feature toggles.
- **No database size target.** Remove waste that does not reduce function and report the measured size.
- **No file-length limit.** Split a module where its behavior separates, not at a line count; Clippy has no file-length lint to enforce one.

Not in v1, with the reason: semantic search (one of thirteen lookup misses was a wording mismatch; the other misses came from unindexed data, redaction, ranking, or evaluation-setup errors), an MCP server, a TUI, token and cost accounting, Claude and Pi loaded-instruction attribution, and Pi branch reconstruction.

## Changing the CLI

The consumer is usually an agent with a shell, so the ordinary path must be one short command and the output must compose with `jq`.

- Ranked lookup (`search`) and exhaustive matching (`grep`) are different contracts and stay different verbs; ranked results are grouped by session.
- Nothing an agent needs exists only on stderr or only in the exit code: the final `end` record carries completeness, staleness, the cursor, and any error with its recovery instruction.
- Enumerated values are validated and have no aliases: an evaluator once passed `claude_code`, got an empty result, and lost four tasks.
- Add a flag only for a lookup that failed without it; questions the verbs do not answer go through read-only `sql`.

## Develop and validate

- The repository is public, and logs contain credentials and private context. Never copy real log content into the repository, fixtures, tests, docs, commit messages, pull requests, or issues: that includes session IDs, paths, project names, and quoted fragments, not only whole lines. A real session UUID once entered a test as a sample identifier and had to be rewritten out of history. Fixtures are synthetic records shaped like an observed variant; cite real evidence outside the repository by `path:line` and its kind only.
- Pull requests and issues outlive the conversation that produced them; a later reader finds them by search and trusts the title and description first. When one is merged, closed, or completed, here or in `Entwining/homebrew-tap`, make the page say what happened. The title and description match what was finally done, or the description opens by stating plainly where they no longer hold. Where needed, a comment records why it closed without merging or was superseded and by what, what was done differently, the evidence that disproved a claim, and where the remaining work went. A claim found wrong after closing is still corrected, and a page that already says all of this needs nothing more.
- A change to how records become rows (`src/adapters`, `normalize.rs`, `redaction.rs`, `outcomes.rs`, `shell.rs`, `code_mode.rs`, `model.rs`, `source.rs`, or a Brush update) raises `PARSER_VERSION`, so that refreshes reindex the files an earlier version indexed; `check.yml` enforces this against the last release for the listed sources. A change to tables or triggers raises `SCHEMA_VERSION`, copies the new `schema.sql` to `tests/fixtures/schema-vN.sql` for the new version, and needs release notes telling users to run `index --full`; `table_changes_raise_the_schema_version` fails when the tables differ from that copy. Views and indexes change without a version: refreshes recreate views and `index` builds indexes, so release notes for a changed index tell users to run `sessidx index`.
- Integration tests are one `tests/it` binary with a module per behavior and shared helpers in `common.rs`, because each top-level `tests/*.rs` file links its own binary.
- Never point a development build at the default database `~/.cache/sessidx/index.db`. Use `--db` with a scratch path and `--root AGENT=PATH`: `--db` does not move the session roots, so a scratch database without `--root` still indexes the real logs under `$HOME`, as one reviewer's run did.
- Before committing, run `cargo fmt` and the Rust checks in `.github/workflows/check.yml`: `cargo deny --locked check`, `cargo fmt --check`, `CARGO_BUILD_WARNINGS=deny cargo clippy --all-targets --locked`, and `cargo test --locked`; a workflow change also needs `actionlint`. Pull requests also run `cargo mutants --in-diff`; run it locally after a rule change with `git diff origin/main > "$TMPDIR/git.diff" && cargo mutants --in-diff "$TMPDIR/git.diff"`. A missed mutant is either a branch no test protects, which needs an assertion, or a mutation that cannot change behavior, which goes into `.cargo/mutants.toml` with its reason. cargo-mutants does not mutate string or regex literals, so a rule written as a pattern is protected only when removing or widening each part of the pattern by hand fails a test.
- Passing `cargo test` is not real-corpus acceptance, and the repository holds no real-corpus gate because one would reference private sessions. A claim about real logs, such as a lookup result, a count, database size, or speed, stays unverified until it is measured with a full build into a scratch `--db` from the real roots. The release targets are warm lookup p95 within 2 s and indexing RSS within 512 MiB, measured on an otherwise idle machine; a contended run is not a measurement.
- Corpus scans read only the session roots, with `rg -j 2` or at most two concurrent readers.
- The skill reaches agents from `main`, not from a release: Claude Code and Codex install it through `.claude-plugin/marketplace.json`, which Codex reads natively, so there is no `.codex-plugin/` manifest, and Pi installs `skills/` from the repository. Homebrew installs the tagged binary, so release a CLI contract change right after it merges, and have its release notes tell Claude Code users to run `claude plugin update sessidx@entwining`, because third-party marketplaces do not update plugins by default.
- Releases are tag-driven. Bump `version` in `Cargo.toml`, add `docs/releases/VERSION.md` (the publish workflow refuses a tag without it), and push a signed `vVERSION` tag; the workflow reruns the checks, creates the GitHub Release, and asks `Entwining/homebrew-tap` to update its formula. That update changes only the tag and revision, and the tap publishes as soon as the bump builds, so packaging belongs in `make build`, which the formula runs: a packaging change ships with the release that contains it. A change to `make build`'s interface or to the tools it runs also needs the formula. Make that change in a tap pull request, so that test-bot shows it still builds the version the formula pins: add a build dependency before the release that needs it, and remove one after.

## Environment traps

- macOS has no `timeout`; use `perl -e 'alarm shift; exec @ARGV' SECONDS COMMAND`.
- Agent sandboxes break measurement tools: inside the Codex sandbox, nested `sandbox-exec` exits 71 and `/usr/bin/time -l` fails, and inside the Claude Code sandbox `samply` fails with `Unknown(1100)`. Run memory, timing, and profiling measurements from an ordinary shell.
- Do not measure a database made by rewriting an APFS clone (`cp -c`) in place: copy-on-write scatters the rewritten blocks, and a cold search on one ran 1.7 s against 0.9 s for a byte copy of the same file. A clone that is only read is a fair cold copy.
- A read-only sandbox cannot open the live WAL database normally; `sqlite3 "file:$HOME/.cache/sessidx/index.db?immutable=1"` reads it, possibly as a stale snapshot.
